- Scope revision before inspecting any real-data model performance: the user requested event-level LOB research, expanding walk-forward evaluation, hit rate, information coefficient and net P&L. The main study now uses decisions every 20 source events, a 100-event prediction horizon and five expanding intraday folds. The original fixed-clock holdout is retained as an optional mode, not presented as the main backtest. No real-data model results had been generated when this revision was made.

- After the first real-data run, added a fail-closed check for missing execution exits and normalised float32 probabilities before float64 log-loss calculation. No model parameters, feature definitions, candidate thresholds or cost assumptions were changed. The real sample had no unpriced-exit cases; the study was rerun after these correctness changes. Presentation changes show the pre-specified fixed-threshold losses alongside the no-trade primary series.

- Independent audit (2026-10-22, `docs/AUDIT.md`): no material bug found, so no pipeline output, model setting, feature or threshold was changed, and the pipeline was not rerun. Added the diagnostic-only `scripts/ic_diagnostics.py`, which reads the saved predictions and raw books and writes `results/diagnostics/ic-decomposition.csv` and `move-composition.csv`. Finding: the INTC/MSFT rank IC (0.52/0.56) mostly reflects half-tick spread-opening moves predicted by L1 queue imbalance; imbalance alone gives an IC of 0.46/0.49. Non-overlapping subsets give the same IC. Decisions taken in the middle of an equal-timestamp burst raise the IC by 0.01–0.03.

## Extension: multi-session crypto replication

- 2026-10-22, before the plan: probed sizes by downloading the 2026-10-01 Binance BTCUSDT `incremental_book_L2`/`trades` and Bitstamp BTCUSD files from Tardis's free endpoint, and counted rows/messages in the BTCUSDT book file. No features, labels or models. 2026-10-01 later became a held-out date; this is disclosed in `EXTENSION_PLAN.md`.
- Plan committed (`5a3cc3d`) before any feature or model computation on the new data.
- Implementation detail settled before any model was fitted (not in the committed plan text): a trade row is marked invalid when its latest book message is more than 1.0 s old (the study's quote-age limit), because otherwise a trade arriving during a book silence would make a stale book look fresh to the quote-age checks. Binance `amount=0` updates for levels outside the 1000-level snapshot are counted (`missing_level_deletes`) and ignored, as expected for a partial snapshot.
- Adapter, downloader and runner committed (`cbf6e4e`) before the development run.
- First development run aborted in BTCUSDT fold 3 (test date 2026-06-01, which has 18 reconnect snapshots and 6 silences) on the equity code's fail-closed check: an entered position's exit at target time plus latency fell in a new segment. Before the abort the log showed only which model validation selected in folds 1–2 (XGBoost); no metrics or P&L were written or viewed. Fix: `require_priced_exits` drops decisions whose exit at any sensitivity latency (0/50/200 ms) lands in a different segment or on a quote older than 1 s. This is a label/exit-availability filter applied to all models before prediction, analogous to the equity rule excluding targets that cross halts or invalid books; it uses knowledge of a gap within 200 ms after the target event, as that rule does. Exclusion counts are reported per date (`exit_gap_exclusions`). No held-out data had been used.
- Development results (test dates 2026-04-01 to 06-01) showed very high ICs (~0.74) for the validation-selected series. A dev-only diagnostic found that about 70–80% of decisions fall on trade rows, which carry the last 100 ms book message, and that IC is ~0.73 at trade-row decisions versus ~0.40 at book-message-row decisions. Much of the apparent predictability therefore comes from trades arriving before the batched book diff that reflects them (a stale-book artefact of the 100 ms depth stream), which also makes the displayed-quote execution diagnostic optimistic. Added, before any held-out fold was run, a reporting-only diagnostic: IC split by decision-row type (`ic_book_row_decisions`, `ic_trade_row_decisions`) in `by-date.csv` and `classification.csv`. Models, features, event definition, thresholds and replication criteria are unchanged; the primary analysis stays as planned. The development phase was rerun (deterministic) to include the diagnostic.
- Held-out folds (2026-07-01 to 10-01) run once from frozen commit `39c1fde`; the development phase was rerun from the same commit first and reproduced the earlier development numbers exactly. After the held-out run, only reporting changed: combined-phase figures were generated, and the logistic coefficients were excluded from Git (fitted-model weights may not be published under Tardis licence clause 9.5(b)). No model, feature, threshold or criterion was changed after seeing held-out results.
